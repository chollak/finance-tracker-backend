# Kapelka для iPhone

Минимальное нативное приложение для быстрой записи трат (FT-161): фраза пишется на диск телефона и уходит в
`POST /api/quick-capture` живого экземпляра, когда он доступен. SwiftUI, iOS 17+, без сторонних библиотек.

Сейчас в нём: настройки, токен в Keychain и очередь (FT-177); голос, команды для Action Button, главный экран со
списком записей (FT-178). Оплаты Apple Pay — FT-179.

## Как устроено

| Что | Где |
|---|---|
| Очередь: запись на диске, правила ответов, повторы | `Kapelka/Queue/` |
| Адрес, токен в Keychain, «Проверить связь» | `Kapelka/Settings/` |
| Отправка при появлении сети и в фоне | `Kapelka/Sync/` |
| Голос: разрешения, распознавание на телефоне, пауза | `Kapelka/Voice/` |
| Команды «Записать трату» и «Отправить очередь» | `Kapelka/Intents/` |
| Экран, список записей, шторка настроек | `Kapelka/UI/`, сборка зависимостей — `Kapelka/App/` |
| Тесты | `KapelkaTests/` |
| Подпись и Info.plist | `Config/` |

- **Очередь** — файл `Application Support/Kapelka/captures.json`. Фраза попадает туда с `clientId` (UUID) и
  временем ввода `capturedAt` до первой попытки отправки. Уходит по одной, старые первыми. Хранятся все ждущие и
  50 последних отправленных или отклонённых.
- **Ответы сервера**:
  - 2xx — «записано» с итогом сервера;
  - 400 — ошибка у записи, больше не уходит; в списке причина по-русски, в файле — текст сервера;
  - 401 и 403 — стоп: очередь пойдёт снова только после «Сохранить» в настройках, с исправленным токеном или адресом;
  - 429 — пауза по `Retry-After`, без заголовка минута; пока приложение открыто, после паузы очередь уходит сама;
  - нет сети, таймаут, 5xx и всё остальное — запись ждёт следующего раза.
- **Повтор** всегда с тем же `clientId`, поэтому сервер второй записи не делает (FT-106). Одновременно идёт одна
  отправка: второй вызов ждёт её конца вместе с ещё одним проходом — за записями, пришедшими за это время.
- **Остановка отправки** (`cancelSending`) — для фона и «Отправить очередь», когда их время вышло: они сначала
  отменяют свой вызов, потом останавливают отправку. Кто ещё ждёт отправку — например, открытое приложение, —
  начинает её снова.
- **Удалить** можно только ждущую запись — свайпом в списке, и она уже не уйдёт. Запись, чей запрос сейчас в пути,
  в списке «Отправляю», и удалить её нельзя: таймаут или обрыв связи не говорят, записал ли её сервер. Не дошла —
  снова «Ждёт», и её можно удалить; если она уже уходила, проверь Mini App — приложение скажет об этом при удалении.
  Записал сервер — правят в Mini App.
- **Когда уходит**: после ввода, при открытии приложения, при каждой новой сети, пока приложение открыто
  (`NWPathMonitor`: Wi-Fi, мобильный интернет, включённый Tailscale), по «Отправить сейчас» и в фоне через
  `BGAppRefreshTask`, когда даст iOS (не раньше чем через 15 минут, время не обещано).
- **Адрес** лежит в настройках приложения (`UserDefaults`), только `https` — `http` принимается лишь для `localhost`
  и `127.0.0.1`, иначе токен шёл бы открытым текстом. **Токен** — только в Keychain: «после первой
  разблокировки», «только на этом телефоне». В логах его нет.

## Голос и команды

- **«Записать трату»** — App Shortcut: открывает приложение, и оно сразу слушает. Пауза около 1,5 с после последнего
  слова, нажатие на кнопку или второе нажатие Action Button — фраза ложится в очередь и уходит. Под кнопкой — итог
  сервера или «В очереди: N». «Отмена» — ничего не записано. Ничего не сказал за 6 с — «Не расслышал».
- **Ушёл с экрана** (заблокировал телефон, «Домой») или звук прервался (звонок, Siri, наушники) — услышанное
  записывается, как после паузы. Ничего не сказано — ничего не записано.
- Распознавание на телефоне после паузы начинает новый кусок с пустого текста; `HeardPhrase` собирает фразу целиком:
  пустой кусок её не стирает, слова после паузы дописываются.
- **«Отправить очередь»** — без открытия приложения, для автоматизаций вроде «подключился к домашнему Wi-Fi».
  Отправляет за то время, что iOS даёт команде, и отвечает «Всё отправлено» или «В очереди: N».
- Обе команды — в `Metadata.appintents` сборки, поэтому видны в «Быстрых командах» и в выборе для Action Button сразу
  после установки. Назначить на кнопку iOS даёт только руками: Настройки → Кнопка действия → «Быстрая команда» →
  Kapelka → «Записать трату». Эта же инструкция — в настройках приложения.
- **Распознаёт телефон**: `SFSpeechRecognizer` для `ru-RU` с `requiresOnDeviceRecognition`, звук никуда не уходит —
  одинаково с сетью и без. Нужна скачанная русская диктовка: Настройки → Основные → Клавиатура — включить
  «Диктовку» и добавить клавиатуру «Русская».
- **Разрешения** на микрофон и распознавание iOS спрашивает один раз. Отказ, нет русской диктовки, распознавание
  недоступно или прервалось — сообщение и клавиатура; услышанное до обрыва остаётся в поле.
- **В симуляторе голос выключен**: первое обращение к `AVAudioEngine.inputNode` там роняет приложение внутри
  CoreAudio («RPC timeout… Apparently deadlocked»), и такое падение не перехватить. Кнопка микрофона в симуляторе
  отвечает «Микрофон недоступен — напиши текстом». На телефоне без микрофона — то же сообщение, а не падение. Голос
  проверяется на iPhone.

## Тесты

```bash
ios/scripts/test.sh
```

Скрипт берёт первый доступный симулятор iPhone. Под тестами приложение — только хозяин: очередь, сеть и голос не
запускаются (`KapelkaMain`). Тесты убирают за собой папки очереди, Keychain и настройки. Конкретный — `KAPELKA_SIMULATOR="iPhone 17 Pro" ios/scripts/test.sh`
(имя или UDID). Нет симулятора — Xcode → Settings → Components → iOS. Подпись для симулятора не нужна. Сборка
кладётся в `ios/DerivedData/`, она в `.gitignore`. `npm run verify` папку `ios/` не проверяет.

## Установка на iPhone с бесплатным Apple ID

Нужны мак с Xcode, свой Apple ID и iPhone с кабелем. Сборка с бесплатным Apple ID живёт **7 дней**.

### Один раз

1. **Apple ID в Xcode.** Xcode → Settings → Apple Accounts → войти. В списке команд появится
   «<имя> (Personal Team)».
2. **Team ID в локальный файл.** Файл вне git, в репозиторий команда не попадает:

   ```bash
   cp ios/Config/Signing.local.xcconfig.example ios/Config/Signing.local.xcconfig
   ```

   В `DEVELOPMENT_TEAM` впиши Team ID — 10 знаков. Где его взять:
   - открой `ios/Kapelka.xcodeproj` → таргет Kapelka → Signing & Capabilities → Team → выбери Personal Team;
   - Xcode запишет `DEVELOPMENT_TEAM = …` в `project.pbxproj` — скопируй значение;
   - верни файл: `git checkout ios/Kapelka.xcodeproj/project.pbxproj`. Иначе Team ID уйдёт в git.

   Если Xcode пишет, что `uz.kapelka.app` занят, задай там же свой `KAPELKA_BUNDLE_ID` и больше его не меняй. Новый
   id — это новое приложение, а очередь и токен остаются у старого.
3. **iPhone.**
   - Подключи кабелем и нажми «Доверять» на телефоне.
   - В Xcode выбери телефон как устройство запуска. Только после этого на телефоне появляется Настройки →
     Конфиденциальность и безопасность → **Режим разработчика**.
   - Включи его, телефон перезагрузится, подтверди.
4. **Запуск.** Выбери телефон в Xcode и нажми Run (⌘R).
   - Первый запуск iOS остановит: «Ненадёжный разработчик».
   - Настройки → Основные → VPN и управление устройством → свой Apple ID → «Доверять».
   - Снова Run.
5. **Настройки приложения** откроются сами при первом запуске:
   - **адрес** — `https://<пк>.<tailnet>.ts.net`, тот же, что у Mini App;
   - **токен** — `SHORTCUT_CAPTURE_TOKEN` из `.env.local` живого экземпляра на ПК.
     - Если его ещё нет: `openssl rand -hex 32`, затем `SHORTCUT_CAPTURE_TOKEN=<токен>` и
       `SHORTCUT_CAPTURE_OWNER=<свой Telegram id>` в `.env.local`, затем `sudo systemctl restart kapelka.service`
       (`docs/knowledge-base/08-development/live-instance.md`, раздел 5).
     - На телефон токен лучше передать через общий буфер мака и iPhone (один Apple ID): на маке скопировать, на
       телефоне вставить.
     - Не пересылай токен в чатах и заметках.
   - **«Проверить связь»** → «Сервер доступен».

   Токен сервер проверит на первой записи. Неверный — на экране «Сервер не принял токен», и очередь ждёт новых
   настроек.

### Раз в 7 дней

Срок подписи вышел — приложение не открывается. Подключи iPhone и снова нажми Run в Xcode. Сборка ставится поверх
старой. Очередь, адрес и токен остаются: тот же bundle id, та же команда.

**Не удаляй приложение с телефона.** Удаление стирает очередь, и неотправленные записи пропадут. Переустановка поверх
их не трогает.

Ограничения бесплатного Apple ID: на телефоне не больше 3 своих приложений, не больше 10 новых bundle id за 7 дней.
Когда приложение приживётся — Apple Developer Program: подпись на год и TestFlight.

## Проверка в авиарежиме

1. Включи авиарежим и Wi-Fi тоже выключи.
2. Нажми Action Button и скажи фразу; так 3 раза (или запиши текстом). На экране — «В очереди: 3», в списке три
   «Ждёт» со временем ввода.
3. Выключи авиарежим, включи Tailscale и открой приложение.
4. Через несколько секунд у записей в списке — итог сервера.
5. В Mini App каждая запись по одному разу, днём ввода (FT-175).
