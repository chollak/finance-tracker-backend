# Kapelka для iPhone

Минимальное нативное приложение для быстрой записи трат (FT-161): фраза пишется на диск телефона и уходит в
`POST /api/quick-capture` живого экземпляра, когда он доступен. SwiftUI, iOS 17+, без сторонних библиотек.

Этот срез — FT-177: настройки, токен в Keychain, очередь и поле для текста. Голос, команды для Action Button и
список записей — FT-178, оплаты Apple Pay — FT-179.

## Как устроено

| Что | Где |
|---|---|
| Очередь: запись на диске, правила ответов, повторы | `Kapelka/Queue/` |
| Адрес, токен в Keychain, «Проверить связь» | `Kapelka/Settings/` |
| Отправка при появлении сети и в фоне | `Kapelka/Sync/` |
| Экран и шторка настроек | `Kapelka/UI/`, сборка зависимостей — `Kapelka/App/` |
| Тесты | `KapelkaTests/` |
| Подпись и Info.plist | `Config/` |

- **Очередь** — файл `Application Support/Kapelka/captures.json`. Фраза попадает туда с `clientId` (UUID) и
  временем ввода `capturedAt` до первой попытки отправки. Уходит по одной, старые первыми. Хранятся все ждущие и
  50 последних отправленных или отклонённых.
- **Ответы сервера**:
  - 2xx — «записано» с итогом сервера;
  - 400 — ошибка у записи, больше не уходит;
  - 401 и 403 — стоп до смены адреса или токена;
  - 429 — пауза по `Retry-After`, без заголовка минута;
  - нет сети, таймаут, 5xx и всё остальное — запись ждёт следующего раза.
- **Повтор** всегда с тем же `clientId`, поэтому сервер второй записи не делает (FT-106). Одновременно идёт одна
  отправка: второй вызов ждёт первую.
- **Когда уходит**: после ввода, при открытии приложения, при каждой новой сети, пока приложение открыто
  (`NWPathMonitor`: Wi-Fi, мобильный интернет, включённый Tailscale), по «Отправить сейчас» и в фоне через
  `BGAppRefreshTask`, когда даст iOS (не раньше чем через 15 минут, время не обещано).
- **Адрес** лежит в настройках приложения (`UserDefaults`). **Токен** — только в Keychain: «после первой
  разблокировки», «только на этом телефоне». В логах его нет.

## Тесты

```bash
ios/scripts/test.sh
```

Скрипт берёт первый доступный симулятор iPhone. Конкретный — `KAPELKA_SIMULATOR="iPhone 17 Pro" ios/scripts/test.sh`
(имя или UDID). Нет симулятора — Xcode → Settings → Components → iOS. Подпись для симулятора не нужна. Сборка
кладётся в `ios/DerivedData/`, она в `.gitignore`. `npm run verify` папку `ios/` не проверяет.

## Установка на iPhone с бесплатным Apple ID

Нужны мак с Xcode, свой Apple ID и iPhone с кабелем. Сборка с бесплатным Apple ID живёт **7 дней**.

### Один раз

1. **Apple ID в Xcode.** Xcode → Settings → Apple Accounts → войти. В списке команд появится
   «<имя> (Personal Team)».
2. **Team ID в локальный файл.** Файл вне git, в репозиторий команда не попадает:

   ```bash
   cp ios/Config/Signing.local.xcconfig.example ios/Config/Signing.local.xcconfig
   ```

   В `DEVELOPMENT_TEAM` впиши Team ID — 10 знаков. Где его взять:
   - открой `ios/Kapelka.xcodeproj` → таргет Kapelka → Signing & Capabilities → Team → выбери Personal Team;
   - Xcode запишет `DEVELOPMENT_TEAM = …` в `project.pbxproj` — скопируй значение;
   - верни файл: `git checkout ios/Kapelka.xcodeproj/project.pbxproj`. Иначе Team ID уйдёт в git.

   Если Xcode пишет, что `uz.kapelka.app` занят, задай там же свой `KAPELKA_BUNDLE_ID` и больше его не меняй. Новый
   id — это новое приложение, а очередь и токен остаются у старого.
3. **iPhone.**
   - Подключи кабелем и нажми «Доверять» на телефоне.
   - В Xcode выбери телефон как устройство запуска. Только после этого на телефоне появляется Настройки →
     Конфиденциальность и безопасность → **Режим разработчика**.
   - Включи его, телефон перезагрузится, подтверди.
4. **Запуск.** Выбери телефон в Xcode и нажми Run (⌘R).
   - Первый запуск iOS остановит: «Ненадёжный разработчик».
   - Настройки → Основные → VPN и управление устройством → свой Apple ID → «Доверять».
   - Снова Run.
5. **Настройки приложения** откроются сами при первом запуске:
   - **адрес** — `https://<пк>.<tailnet>.ts.net`, тот же, что у Mini App;
   - **токен** — `SHORTCUT_CAPTURE_TOKEN` из `.env.local` живого экземпляра на ПК.
     - Если его ещё нет: `openssl rand -hex 32`, затем `SHORTCUT_CAPTURE_TOKEN=<токен>` и
       `SHORTCUT_CAPTURE_OWNER=<свой Telegram id>` в `.env.local`, затем `sudo systemctl restart kapelka.service`
       (`docs/knowledge-base/08-development/live-instance.md`, раздел 5).
     - На телефон токен лучше передать через общий буфер мака и iPhone (один Apple ID): на маке скопировать, на
       телефоне вставить.
     - Не пересылай токен в чатах и заметках.
   - **«Проверить связь»** → «Сервер доступен».

   Токен сервер проверит на первой записи. Неверный — на экране «Сервер не принял токен», и очередь ждёт новых
   настроек.

### Раз в 7 дней

Срок подписи вышел — приложение не открывается. Подключи iPhone и снова нажми Run в Xcode. Сборка ставится поверх
старой. Очередь, адрес и токен остаются: тот же bundle id, та же команда.

**Не удаляй приложение с телефона.** Удаление стирает очередь, и неотправленные записи пропадут. Переустановка поверх
их не трогает.

Ограничения бесплатного Apple ID: на телефоне не больше 3 своих приложений, не больше 10 новых bundle id за 7 дней.
Когда приложение приживётся — Apple Developer Program: подпись на год и TestFlight.

## Проверка в авиарежиме

1. Включи авиарежим и Wi-Fi тоже выключи.
2. Запиши 3 фразы. На экране — «В очереди: 3».
3. Выключи авиарежим, включи Tailscale и открой приложение.
4. Через несколько секунд на экране итог последней записи.
5. В Mini App каждая запись по одному разу, днём ввода. День ввода сервер учитывает с FT-175. До неё запись
   ложится днём отправки.
