# FT-088 — как проверить голос в mini app

Служебная страница `/dev/voice-check` пишет 5 секунд с микрофона, показывает формат и размер записи,
отправляет её в `POST /api/voice/voice-input` и собирает отчёт, который можно скопировать одной кнопкой.
В приложении на неё нет ссылок.

## Шаги

1. Запустить локальный контур как обычно: `npm run dev:miniapp -- --chat-id=<ваш telegram id>`.
   В выводе будет адрес туннеля `https://….trycloudflare.com`.
2. Временно направить кнопку меню бота на страницу проверки:
   `npm run miniapp:menu -- set --url=https://<туннель>/dev/voice-check --chat-id=<ваш telegram id>`.
   Важно открыть страницу именно кнопкой меню: обычная ссылка в Telegram открывается во встроенном
   браузере, а не в WebView mini app, и проверка будет не про то.
3. На каждом устройстве — iPhone, Android, Telegram Desktop, по желанию браузер — открыть бота, нажать
   кнопку меню, затем «1. Записать 5 секунд». Сказать фразу **без сумм**, например «проверка микрофона,
   раз, два, три», — так запись в базе не создастся. Потом «2. Отправить на распознавание».
4. «Скопировать отчёт» и прислать отчёты со всех устройств. Вывод пишем в `docs/tasks/decisions.md`:
   голос в mini app везде / с запасным путём «Голосовое — в чат бота» / не делаем.
5. Вернуть кнопку меню на главную: `npm run miniapp:menu -- set --url=https://<туннель> --chat-id=<id>`.

## Что смотреть в отчёте

| Строка | Что значит |
|---|---|
| `mediaDevices: нет` или `MediaRecorder: нет` | WebView не умеет записывать — голос только через бота |
| `Доступ к микрофону: нет (NotAllowedError)` | Telegram или система не дали разрешение; проверить настройки и повторить |
| `Форматы записи` | Какой формат пойдёт на сервер; iOS обычно `audio/mp4`, Android и Desktop — `audio/webm` |
| `Распознавание: ошибка 400 (Invalid file type …)` | Формат не прошёл фильтр сервера — добавить его в `ALLOWED_AUDIO_TYPES` |
| `Распознавание: «…»` | Whisper понял запись — путь работает целиком |
