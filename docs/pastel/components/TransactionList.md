# TransactionList

Список операций, сгруппированный по дням: подпись дня и белая карточка со строками.

- Подпись дня — стиль `label`, `muted` («Сегодня», «Вчера», дальше «Понедельник, 12 октября»). В истории справа итог дня: 13px/800, в сумах, со знаком; доход — `income`, расход — `muted`. Если в дне есть доллары, итог пересчитан по курсу и начинается с «≈».
- Карточка `card`, `radius-card`, отступ 4px 8px. Строки без разделителей, высота `size-row` (60px).
- **Строка — две кнопки.** Кружок категории 40px (пастель категории, первая буква 15px/800, `pastel-ink`) в зоне 52×60 — сразу открывает выбор категории. Остальная строка — открывает карточку операции (TxnSheet).
- В строке: название категории (`body-strong`) и заметка (13px, `muted`; в истории — «заметка · счёт»), справа сумма 15px/800. Расход — `ink` со знаком «−», доход — `income` со знаком «+».
- Сумма в сумах без единицы, в другой валюте — с единицей: «+300,00 USD».
- Только что исправленная строка 2 секунды обведена изнутри 2px `ink`, `radius-control`.
- Длинная заметка обрезается многоточием, сумма — никогда.
- **В коде (FT-148): «Не входит в остаток».** На экране счёта запись с `countsInBalance: false` (раньше даты
  открытия, в день открытия до первого запуска — FT-163, запись в другой валюте) начинает подпись с «Не входит в
  остаток» (13px, `muted`, вес 600, как `label`), за ней заметка: «Не входит в остаток · Кофе». Метка одна на все
  причины — правило одно, `countsInBalance()`; метку ставит только `false` от сервера, ответ без поля строки не
  помечает. Метка идёт первой и не обрезается; шире всей подписи (+30% на узком телефоне) — переносится на вторую
  строку. Заметка режется многоточием, а если рядом с меткой ей остаётся меньше 56px (« · » и три буквы) — не
  показывается вовсе, без одинокого «· …». Сумма и цвет не меняются, «Без заметки» после метки не пишется. Так
  начальный остаток и строки без метки дают остаток наверху. Перемещения — в [AccountMoves](AccountMoves.md). В
  истории метки нет: там нет остатка, с которым сверять список, и записи истории не несут `countsInBalance`.
