# Набор типичных фраз для проверки разбора (#307)

Чтобы правку промпта, параметров запроса или кода после ИИ можно было сравнить «до и после» до мержа, а не по живым
записям после.

## Что это

`tests/fixtures/capturePhrases.json` — 54 типичные фразы: кофе, такси, «вчера», «в пятницу», «нал», «$», «25.000»,
«25к», «1,5 млн», голое «45», две и три траты, позиция без суммы, перевод себе, «мне вернули», зарплата, голосовая
расшифровка с числами словами, опечатки, узбекские слова. **Фразы придуманы** — репозиторий публичный, из живой базы
сюда ничего не берётся.

У каждой фразы:

| Поле | Что в нём |
|---|---|
| `phrase`, `covers` | фраза и какой случай она представляет |
| `ai` | ответ модели на эту фразу (JSON содержимого ответа) или `null`, если фразу читает быстрый путь текста и ИИ не спрашивают |
| `aiSource` | `recorded` — ответ модели как пришёл; `edited` — ответ модели, в котором промах исправлен руками; `constructed` — написан руками, чтобы показать форму ответа, которую код должен пережить |
| `expected` | какие записи должны получиться: тип и смысл, сумма в минорных единицах, валюта, дата, категория, счёт, «Нужно проверить»; позиции без суммы |
| `knownIssue` | фраза, которую нынешний код пишет неверно: номер issue, пояснение и `now` — что пишется сейчас |

День всех фраз — `today` набора (2026-11-18, среда): «вчера» и «в пятницу» считаются от него. Пользователь стенда —
новый, со стартовыми категориями и двумя счетами: «Карта» (по умолчанию) и «Наличные». Долларового счёта нет, поэтому
запись в долларах ложится на «Карту» с «Нужно проверить» — так и в приложении.

## Две проверки на одном наборе

Обе идут через `scripts/capture-eval/captureStand.ts`: фраза пишется так же, как в приложении — быстрые пути текста,
потом ИИ, потом настоящая запись с категорией и счётом в SQLite-файле во временной папке.

**1. Без сети, в `npm run verify`** — `tests/capturePhraseSet.test.ts`. Ответ ИИ берётся из набора (`ai`), его читает
настоящий `OpenAITranscriptionService` поверх подменённой сети, запись пишут настоящие use case. Проверяется весь путь
после ИИ. Фраза с `ai: null` обязана обойтись без ИИ; фраза с ответом обязана спросить ИИ ровно один раз.
Фразы с ответом ИИ тест затем «говорит голосом» (#301): расшифровка — текст фразы, запись — через
`ProcessVoiceInputUseCase` (`captureVoice` стенда). Голос должен записать то же, что текст. Фразы с `ai: null` голосом
не проверяются: голос быстрыми путями не читается, а ответа ИИ для них в наборе нет.
Фразу с `knownIssue` тест держит на том, что код пишет сейчас (`now`), и печатает список таких фраз; когда код
исправлен и пишет `expected`, тест падает — пометку пора снять.

**2. С настоящей моделью, вне `verify`** — `npm run eval:capture`. Фразы уходят в OpenAI с промптом приложения, и то,
что записалось, сравнивается с тем же `expected`.

```bash
scripts/nvm-exec.sh npm run eval:capture                       # один прогон набора
scripts/nvm-exec.sh npm run eval:capture -- --repeat=3         # каждую фразу три раза: виден разброс
scripts/nvm-exec.sh npm run eval:capture -- --only=two-items,friday-dinner
scripts/nvm-exec.sh npm run eval:capture -- --repeat=3 --temperature=0 --schema   # проба параметров запроса
scripts/nvm-exec.sh npm run eval:capture -- --json=/tmp/eval.json                 # итог и ответы модели в файл
scripts/nvm-exec.sh npm run eval:capture -- --jobs=1           # фраз одновременно: 1–8, по умолчанию 4
scripts/nvm-exec.sh npm run eval:capture -- --help             # справка по параметрам
```

- Ключ — `OPENAI_API_KEY` из окружения или `.env.local` / `.env` копии. Без ключа — сообщение и код выхода 2. Ключ,
  запрос и его заголовки не печатаются; печатаются придуманные фразы набора и что из них записалось.
- Стоит денег: один запрос модели разбора на фразу и повтор — центы за весь набор.
- Код выхода: 0 — прогон состоялся (расхождения — это находка, а не сбой); 1 — модель не ответила хотя бы раз;
  2 — нет ключа или неверный параметр.
- В промпт попадают выученные паттерны копии. Если в копии есть `data/patterns.json`, отчёт об этом предупреждает:
  для сравнения «до/после» запускайте в копии без этого файла (свежий worktree) — тогда в промпте только seed.

Что печатает: сколько фраз читает ИИ и сколько — быстрый путь; сколько прогонов совпало с ожиданием; сколько фраз
совпало во всех прогонах; сколько фраз с разбросом (прогоны одной фразы записали разное); расхождения по полям —
число записей, сумма, валюта, тип (тип и смысл записи), категория, дата, счёт, «Нужно проверить»; и по каждой
разошедшейся фразе — что ожидалось и что записано в каждом прогоне.

`--temperature=X` и `--schema` (строгая JSON-схема ответа, `scripts/capture-eval/answerSchema.ts`) меняют только эти
параметры запроса: скрипт дописывает их в тело запроса, который собрал рабочий код, сам код не трогается.

## Как сравнивать правку

1. До правки: `npm run eval:capture -- --repeat=3 --json=/tmp/before.json`.
2. После правки (промпт, параметры запроса, код после ИИ): то же в `/tmp/after.json`.
3. Сравнить итог: совпавших прогонов, расхождения по полям, разброс. Модель без `temperature: 0` отвечает по-разному,
   поэтому разница в один-два прогона из девяноста — шум; смотрите на фразы, которые изменились во всех повторах.
4. Таблицу «было/стало» — в описание PR.

## Как менять набор

- Новая фраза — придуманная. Добавьте её с `"ai": null` и пустым `expected`, запустите
  `npm run eval:capture -- --only=<id> --json=/tmp/one.json`: в файле будет ответ модели (`answer`) и что записалось
  (`outcome`). Перенесите ответ в `ai`, а в `expected` запишите то, что **должно** получиться по здравому смыслу — не
  обязательно то, что получилось.
- Модель ошиблась, а код прав — исправьте ответ в `ai` руками и поставьте `aiSource: "edited"`: офлайн-тест проверяет
  код, а промах модели покажет `eval:capture`.
- Код пишет неверно при верном ответе — не подгоняйте `expected`: добавьте `knownIssue` с номером issue и `now`.
- Изменилось поведение по решению (например, долги в #266) — меняйте `expected` в том же PR, что и код.

## Проба `temperature: 0` и строгой схемы (2026-11-18)

Модель `gpt-4.1-mini`; набор на день пробы — 50 фраз, 31 из них идёт в ИИ, по 3 повтора — 93 прогона на вариант.

| | как в приложении | `temperature: 0` | схема | `temperature: 0` + схема |
|---|---|---|---|---|
| Совпало прогонов | 78 | 76 | 79 | 81 |
| Фраз, совпавших во всех прогонах (из 31) | 24 | 25 | 25 | 27 |
| Фраз с разбросом | 3 | 1 | 2 | 0 |
| Расходится число записей | 0 | 0 | 0 | 0 |
| Расходится сумма | 0 | 0 | 0 | 0 |
| Расходится валюта | 0 | 0 | 0 | 0 |
| Расходится тип | 4 | 5 | 3 | 3 |
| Расходится категория | 6 | 6 | 4 | 3 |
| Расходится дата | 3 | 3 | 3 | 3 |
| Расходится счёт | 0 | 0 | 0 | 0 |
| Расходится «Нужно проверить» | 5 | 6 | 7 | 6 |

Условие задачи — включать, только если не хуже ни по одному полю. Все три варианта хуже по «Нужно проверить» (на
один-два прогона): с ними «перевел маме 500000» получает «Нужно проверить» во всех повторах, а сейчас — в одном из
трёх. Поэтому **в рабочий запрос ничего не добавлено**. Вместе `temperature: 0` и схема убирают разброс и дают больше
совпадений; вернуться к ним стоит, когда будет решено, должен ли перевод другому человеку идти с «Нужно проверить».

Три расхождения даты во всех вариантах — одна фраза «коммуналка 25го 320000» (#300); расхождения типа — в основном «я вернул
Азизу 200000»: модель пишет обычный расход с «Нужно проверить», а не возврат долга, как просит промпт.
