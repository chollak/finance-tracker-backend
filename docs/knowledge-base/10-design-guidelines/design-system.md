# Design System

Status: единственный действующий документ по дизайну. Обновлён 2026-08-13.

Заменяет собой `design-guidelines.md`, `style-direction.md`, `docs/DESIGN_SYSTEM_SUMMARY.md` и `08-development/design-system.md` — все они перенесены в `docs/archive/`.

## Главное правило

**Источник правды — код, а не этот документ.** Шрифт, цвета, радиусы, тайминги и тач-таргеты заданы токенами. Здесь описано только то, что кодом не выражается: смысл ролей, иерархия действий и причины решений.

Если документ разошёлся с токенами — прав код, а документ надо чинить. Именно так и появилась путаница: `design-guidelines.md` предписывал шрифт Inter, когда в коде уже полгода стоял Onest.

## Визуальный тезис

**Нейтральный интерфейс, семантические цвета денег.**

Оболочка — чёрно-бело-серая. Цвет появляется только там, где несёт финансовый смысл: доход, расход, предупреждение, здоровое состояние.

Это защищает от типичной ошибки финансовых приложений: когда зелёным красят каждую важную кнопку, и `+ расход` начинает выглядеть как хорошая новость.

Ориентиры настроения: Linear — структура и дисциплина отступов; Wise/Revolut — ясность денег; нативные Telegram Mini App — очевидные тач-таргеты без визуального шума.

## Роли цвета

| Роль | Токены | Для чего | Никогда для |
|---|---|---|---|
| Основное действие | `primary`, `secondary`, `muted`, `foreground` | Отправить, создать, открыть, навигация | Смысла «доход» или «успех» |
| Доход / успех | `income`, `success` | Доходы, здоровый бюджет, остаток, положительное состояние | Обычных кнопок |
| Расход / опасность | `expense`, `destructive` | Расходы, удаление, просрочка, отрицательное состояние | Украшения |
| Предупреждение | `warning` | Близко к лимиту, требует внимания, статус пробного периода | Основной навигации |
| Оболочка | `background`, `card`, `border`, `muted` | Навигация, карточки, вкладки, шторки | Смысла данных |

Сырые палитровые классы Tailwind в продуктовом интерфейсе не используются — только семантические токены.

**Графики:** ровно шесть токенов `--color-chart-1…6`. Больше цветов не добавлять; если категорий больше шести, сворачивать хвост в «Другое».

## Иерархия действий

1. Одно глобальное мобильное действие — центральная `+` в доке, добавление транзакции.
2. Действия конкретного экрана живут внутри страницы, а не висят над доком.
3. На десктопе фиксированные кнопки допустимы — там нет нижней навигации.
4. Пустые состояния имеют собственный призыв к действию: они объясняют первый шаг в контексте.

Центральная `+` — нейтральное основное действие, а не «успех». Зелёный к ней не применяется.

## Навигация

Нижний док: `Главная` · `История` · `+` · `Бюджеты` · `Ещё`.

`Ещё` не ведёт на страницу — открывает шторку поверх текущего экрана со второстепенными разделами (`Долги`, `Аналитика`) и лимитами подписки. Список разделов задан в `webapp/src/features/more-menu/model/destinations.ts` и используется и шторкой, и страницей `/more`, которая остаётся для десктопа и прямых ссылок.

Активные элементы навигации — нейтральные, не зелёные. Конкурирующих плавающих кнопок на мобильных нет.

## Раскладка страниц

Основные вкладки внутри `Layout` — `PageShell` как `div`, потому что `Layout` уже владеет `<main>` и отступом под док:

```tsx
<PageShell>
  <PageHeader title="Главная" subtitle="Обзор ваших финансов" />
  <SectionStack>{/* карточки */}</SectionStack>
</PageShell>
```

Отдельные формы и детальные страницы — `PageShell as="main"`, они вне `Layout`:

```tsx
<PageShell as="main" className="max-w-2xl">
  <FormPageHeader title="Новая транзакция" onBack={() => navigate(-1)} />
</PageShell>
```

Не совмещать `container` с конфликтующим `max-w-*` на одном элементе без явного обоснования.

## Примитивы

Импорт из `@/shared/ui`:

```tsx
import { Button, Card, PageHeader, PageShell, SectionStack } from '@/shared/ui';
```

| Примитив | Назначение |
|---|---|
| `PageShell` | Единая ширина и отступы страницы |
| `SectionStack` | Вертикальный ритм между секциями |
| `PageHeader` / `FormPageHeader` | Заголовок вкладки / формы с кнопкой назад |
| `Card` | Стандартный контейнер содержимого |
| `AmountText` | Деньги: табличные цифры, `UZS` визуально второстепенен |
| `MetricStat` | Небольшая финансовая метрика |
| `Dock`, `DockItem`, `DockSeparator` | Мобильная нижняя навигация |
| `EmptyState` | Пустое состояние с призывом к действию |

Плюс формы, диалоги, шторки, вкладки и сегментированные контролы.

Варианты `Button`: `default`, `destructive`, `outline`, `secondary`, `ghost`, `link`, `income`, `expense`.
Варианты `Badge`: `default`, `secondary`, `destructive`, `outline`, `income`, `expense`, `warning`, `success`.

## Типографика

Шрифт — Onest через `--font-family-sans`, веса 400–800. Заголовки — только через `PageHeader` / `FormPageHeader`, заголовки карточек — через `CardTitle`. Произвольные размеры текста заводить не следует, кроме обоснованных локальных исключений.

## Что задано токенами

Эти величины **не переписывать в документе** — смотреть в `globals.css`:

- Радиусы: `--radius-sm` … `--radius-3xl`, `--radius-full`. Стандартная карточка — `rounded-2xl`; `rounded-3xl` только для намеренно акцентных карточек и модалок.
- Тач-таргеты: `--touch-target` (минимум) и `--touch-target-lg` (желательно).
- Анимации: `--duration-fast/normal/slow/stagger` и `--ease-out/in-out/spring`.

## Проверка перед завершением работы над UI

```bash
npm run verify
```

Технической проверки недостаточно. Обязательно смотреть скриншоты:

```bash
BASE_URL=http://127.0.0.1:3000 VIEWPORT_WIDTH=390 VIEWPORT_HEIGHT=844 OUT_DIR=/tmp/ui-audit ROUTES=/,/transactions,/budgets,/more npm run design:audit
```

Снимать минимум на 375, 390 и 412 px. Оценивать визуально: иерархию, ритм отступов, семантику цвета, налезание дока на содержимое. И убедиться, что видимые накладки вроде TanStack Query Devtools не приняты за продуктовый интерфейс.

## Действующие решения

- Центральная `+` в доке нейтральная, не зелёная.
- Активные элементы навигации нейтральные.
- Зелёный остаётся за доходом, успехом и здоровым бюджетом.
- На странице бюджетов нет плавающей кнопки создания — создание внутри страницы или в пустом состоянии.
- `Долги` и `Аналитика` остаются второстепенными, пока данные не докажут обратное.

## Что упразднено

| Упразднено | Причина |
|---|---|
| Шрифт Inter | В коде Onest с весами 400–800, выбран как более подходящий для кириллицы |
| Палитра `lime` / `lavender` | Противоречит тезису «нейтральный интерфейс, семантические цвета денег» |
| Пакет `webapp/src/design-system/` | Удалён, заменён примитивами `shared/ui` и токенами |

Если эти названия встретились в каком-то тексте — текст устарел.
