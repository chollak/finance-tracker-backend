# iPhone Action Button → быстрая запись траты (Telegram + прямой API)

> **Status:** на 2026-10-27 доступны два пути.
> **Вариант через Telegram** (`FT-076`) — безопасный MVP без кода и без токенов, работает где угодно.
> **Прямой вызов `POST /api/quick-capture`** (`FT-075`, `FT-155`) — работает и на живом экземпляре с
> `NODE_ENV=production`: заголовок `X-Shortcut-Capture-Token`, токен привязан к одному владельцу
> (`SHORTCUT_CAPTURE_OWNER`), отзывается новым значением и перезапуском. API открыт только в tailnet.
> Шаги настройки не проверены на устройстве — их выполняет и проверяет Шукур на своём iPhone (FT-160,
> см. [Что нельзя проверить из WSL](#что-нельзя-проверить-из-wsl)).

---

## Цель

Записать трату в момент оплаты, не открывая приложение вручную и не вспоминая, где в интерфейсе кнопка «добавить».
Идеал — одно нажатие физической кнопки, продиктовал «такси 18к», получил подтверждение.

Универсальная версия этого — **Кнопка действия → Shortcut → чат с ботом → отправить** (варианты A–C). Это не одно
нажатие, но это ввод «на ходу», не требующий поиска приложения и навигации по экранам, и он работает всегда.

Настоящее «одно нажатие» даёт [вариант D](#вариант-d--прямой-вызов-api-одно-нажатие) — прямой вызов API
живого экземпляра по адресу в tailnet, с токеном владельца.

---

## Текущий безопасный MVP

```text
Нажать Кнопку действия
  → Shortcut спрашивает: «Что потратил?»
  → диктуешь или печатаешь: «такси 18к»
  → Shortcut копирует текст в буфер обмена
  → Shortcut открывает чат с ботом в Telegram
  → вставляешь и отправляешь
  → бот распознаёт и отвечает: «Записал · Такси · 18 000 сум · Транспорт»
```

Ничего нового на бэкенде для этого не нужно: обычное текстовое сообщение боту уже проходит через тот же
Quick Capture, что и ввод в Mini App (`quickCaptureService.capture({ source: 'telegram' })`,
см. [`docs/QUICK_CAPTURE_API.md`](QUICK_CAPTURE_API.md#telegram-uses-the-same-boundary)). Голосовое сообщение боту
идёт через транскрипцию и отвечает тем же подтверждением с префиксом 🎤.

**Что даёт:** запись за ~5 секунд без поиска приложения, работает с диктовкой, ничего секретного не хранится на телефоне.
**Что не даёт:** полностью автоматической отправки. Финальные «вставить» и «отправить» делаются руками — см.
[Ограничения](#ограничения).

## Почему «скопировать и открыть», а не ссылка с готовым текстом

Соблазнительный вариант — открыть сразу `https://t.me/<BOT_USERNAME>?text=такси%2018к`. Он не заложен в основную
инструкцию по двум причинам:

- **Префилл текста для ботов не гарантирован.** Поведение `tg://resolve?domain=<bot>&text=...` и
  `https://t.me/<bot>?text=...` в текущем Telegram для iOS зависит от версии клиента и типа чата; из WSL это не
  проверить. Если у Шукура сработает — отлично, вариант C ниже.
- **`?start=<payload>` не подойдёт принципиально.** Такая ссылка присылает боту команду `/start payload`, а
  обработчик записи пропускает всё, что начинается с `/`
  (`src/delivery/messaging/telegram/handlers/messageHandlers.ts:135`) — операция просто не запишется, придёт
  приветствие. Это проверено по коду, а не предположение.

Вариант с буфером обмена не зависит ни от версии Telegram, ни от формата deep link.

## Что должен заполнить Шукур

| Плейсхолдер | Что это | Где взять |
|---|---|---|
| `<BOT_USERNAME>` | username бота **без `@`** | бот живого экземпляра — Kapelka на ПК (`@kapelkabot` или имя, которое дал BotFather при переезде FT-159); до переезда — @FinanceTrackerDevBot. Открыть чат с ботом в Telegram → имя вида `@kapelkabot` → в URL пишется `kapelkabot` |

Для вариантов A–C больше ничего подставлять не нужно: ни chat id, ни токена, ни URL туннеля. Один раз перед первым
использованием нужно открыть чат с ботом и нажать `/start`, иначе Telegram не даст писать в него из вставки.
У [варианта D](#вариант-d--прямой-вызов-api-одно-нажатие) свой набор плейсхолдеров — он описан там же.

## Настройка Shortcut на iPhone

Названия пунктов меню приведены для русской локализации iOS; в другой версии системы формулировки могут немного
отличаться — смысл действий тот же.

### Вариант A — основной: буфер обмена + открытие чата

1. Открыть приложение **«Быстрые команды»** → вкладка **«Мои команды»** → **«+»** в правом верхнем углу.
2. Нажать на название новой команды → **«Переименовать»** → `Записать трату`.
3. Добавить действие **«Запросить ввод»** (поиск: `Запросить ввод` / `Ask for Input`):
   - **Тип ввода:** `Текст`
   - **Вопрос:** `Что потратил?`
   - Диктовка включается микрофоном на клавиатуре — отдельное действие для этого не нужно.
4. Добавить действие **«Скопировать в буфер обмена»** (`Copy to Clipboard`):
   - Входное значение — **«Введённый текст»** (`Provided Input`) из предыдущего шага. Обычно подставляется
     автоматически; если нет — нажать на поле и выбрать результат шага 3.
5. Добавить действие **«Открыть URL»** (`Open URLs`) и вписать:

   ```text
   tg://resolve?domain=<BOT_USERNAME>
   ```

   Если по этой ссылке Telegram не открывается — заменить на:

   ```text
   https://t.me/<BOT_USERNAME>
   ```

6. Сохранить (**«Готово»**).
7. При первом запуске iOS спросит разрешение открывать Telegram — разрешить.

Использование: запустить команду → продиктовать/напечатать → в открывшемся чате долгое нажатие на поле ввода →
**«Вставить»** → отправить.

### Вариант B — альтернатива: лист «Поделиться»

Если ручная вставка раздражает, можно отдать текст системному листу отправки:

1. Шаги 1–3 из варианта A.
2. Вместо шагов 4–5 добавить действие **«Поделиться»** (`Share`), вход — **«Введённый текст»**.
3. В открывшемся листе выбрать **Telegram** → чат с ботом → отправить.

Действий примерно столько же, но не трогается буфер обмена. Что удобнее — решается только на устройстве.

### Вариант C — эксперимент: текст прямо в ссылке

Проверить **самому**, работает ли префилл в текущем Telegram:

1. Шаги 1–3 из варианта A.
2. Добавить действие **«Кодировать URL»** (`URL Encode`), вход — **«Введённый текст»**.
3. Добавить **«Открыть URL»** со значением, собранным из текста и результата шага 2:

   ```text
   tg://resolve?domain=<BOT_USERNAME>&text=[результат URL Encode]
   ```

Если текст подставился в поле ввода Telegram — остаётся только нажать «отправить», и это самый быстрый вариант.
Если поле пустое или Telegram открыл не тот экран — вернуться к варианту A. Из WSL этот результат предсказать нельзя.

### Вариант D — прямой вызов API (одно нажатие)

> Работает на живом экземпляре с `NODE_ENV=production` (FT-155, решение 2026-10-26): API открыт только в tailnet,
> Shortcut доказывает себя токеном, а записи всегда пишутся на одного владельца — `SHORTCUT_CAPTURE_OWNER`.
> Если на сервере токен не настроен, он отвечает `403 SHORTCUT_CAPTURE_DISABLED` — явно, а не молча.

Это единственный вариант «одно нажатие → записано», без вставки и без открытия Telegram. Shortcut отправляет
HTTP-запрос прямо на сервер и показывает ответ.

#### Настройка сервера (один раз, руками Шукура)

В `.env.local` живого экземпляра:

```bash
# токен: случайный, не короче 32 символов
openssl rand -hex 32
```

```text
SHORTCUT_CAPTURE_TOKEN=<результат openssl rand -hex 32>
SHORTCUT_CAPTURE_OWNER=<свой Telegram id — тот, что в ALLOWED_TELEGRAM_IDS>
```

Затем перезапустить сервис. Задаются оба или ни одного: токен короче 32 символов, одно без другого или владелец не из
`ALLOWED_TELEGRAM_IDS` — сервер не стартует и пишет в лог, что не так (значение токена в лог не попадает). Так ошибка
видна сразу при перезапуске, а не потом на телефоне у кассы.

#### Что нужно подставить в Shortcut

| Плейсхолдер | Что это | Где взять |
|---|---|---|
| `<BASE_URL>` | адрес сервера | живой экземпляр — `https://<пк>.<tailnet>.ts.net` (Tailscale на iPhone включён). При разработке — `https://<tunnel-host>` из `npm run dev:miniapp` или `http://<ip-компьютера>:3000` в той же Wi-Fi-сети |
| `<SHORTCUT_CAPTURE_TOKEN>` | токен | то же значение, что в `.env.local` сервера |

Токен придумывает и хранит Шукур. В репозитории и в этом документе его нет и быть не должно — только плейсхолдер.
`X-Shortcut-User-Id` больше не нужен: владельца знает сервер. Если его всё же передать, он должен совпадать с
владельцем, иначе `403 ACCESS_DENIED` — токен не пишет за другого.

#### Проверка из терминала перед настройкой телефона

С устройства в tailnet (или с самого ПК):

```bash
curl -sS -X POST <BASE_URL>/api/quick-capture \
  -H 'Content-Type: application/json' \
  -H 'X-Shortcut-Capture-Token: <SHORTCUT_CAPTURE_TOKEN>' \
  -d '{"text":"такси 18к","clientId":"check-1"}'
```

Ожидаемо: `"success": true` и `"source": "ios_shortcut"` в `data`. Повтор той же команды с тем же `clientId` вернёт
ту же запись с `"repeated": true` и ничего не добавит.

#### Настройка Shortcut

1. Шаги 1–3 из [варианта A](#вариант-a--основной-буфер-обмена--открытие-чата) (создать команду, «Запросить ввод»).
2. Добавить действие **«Получить содержимое URL»** (`Get Contents of URL`):
   - **URL:** `<BASE_URL>/api/quick-capture`
   - **Метод:** `POST`
   - **Заголовки:**
     - `Content-Type` → `application/json`
     - `X-Shortcut-Capture-Token` → `<SHORTCUT_CAPTURE_TOKEN>`
   - **Тело запроса:** `JSON`, поле `text` (тип «Текст») со значением **«Введённый текст»** из шага 1. Желательно
     ещё поле `clientId` — своё для каждого запуска, из букв, цифр и `-`, до 64 символов (например, «Текущая дата»,
     отформатированная как `yyyyMMdd-HHmmss-SSS`): если команда повторит тот же запрос, второй записи не будет.
3. Добавить **«Получить значение из словаря»** (`Get Dictionary Value`): ключ `data.ack.title`, вход — результат шага 2.
4. Добавить **«Показать уведомление»** (`Show Notification`) с этим значением — чтобы видеть `Записал` /
   `Нужно проверить` / `Не нашёл операцию` без открытия приложения.
5. Сохранить и привязать к Кнопке действия так же, как в варианте A.

`userId` и `source` в теле передавать не нужно: сервер пишет на владельца и сам ставит `source: "ios_shortcut"`.
Если их всё же передать — они будут проигнорированы. Точный вид действий на телефоне проверяется в FT-160.

> **Командой с токеном не делиться.** Ссылка на команду (iCloud, «Поделиться», AirDrop) уносит её целиком — вместе с
> заголовком `X-Shortcut-Capture-Token`. Если команду всё же нужно передать (на свой второй телефон), сначала заменить
> значение заголовка вопросом при импорте (в настройках команды — «Настроить при импорте» / Import Questions), чтобы
> токен вводился на новом устройстве; или поделиться как есть и сразу [отозвать токен](#отзыв-токена).

#### Отзыв токена

Если телефон потерян или токен куда-то утёк: новый токен (`openssl rand -hex 32`) в `SHORTCUT_CAPTURE_TOKEN` в
`.env.local` и перезапуск сервиса. Старый перестаёт работать сразу — сервер помнит только текущее значение. Потом
новый токен — в заголовок Shortcut. Чтобы выключить Shortcut совсем, убрать обе переменные и перезапустить.

#### Что ломается и почему

| Симптом | Причина | Что делать |
|---|---|---|
| `403 SHORTCUT_CAPTURE_DISABLED` | на сервере (production) не заданы `SHORTCUT_CAPTURE_TOKEN` и `SHORTCUT_CAPTURE_OWNER` | задать оба в `.env.local` и перезапустить, см. «Настройка сервера» |
| `401 INVALID_SHORTCUT_TOKEN` | заголовок `X-Shortcut-Capture-Token` пустой, не долетел или не совпал | сверить с `.env.local`; после смены токена — обновить его в Shortcut |
| `403 ACCESS_DENIED` | в Shortcut остался заголовок `X-Shortcut-User-Id` с другим id | убрать заголовок — он не нужен |
| `403 ACCESS_NOT_ALLOWED` | владелец не в `ALLOWED_TELEGRAM_IDS` (вне production) | добавить id в список или поправить владельца |
| `403 SHORTCUT_CAPTURE_TOKEN_REQUIRED` | сервер для разработки (не production), запрос с телефона, а токен не задан | задать `SHORTCUT_CAPTURE_TOKEN` в `.env.local` и перезапустить |
| `400 VALIDATION_ERROR` | пустой `text`, тело не JSON или `clientId` с недопустимыми символами | тип тела в Shortcut — `JSON`, поле `text` не пустое |
| `429 AI_RATE_LIMIT_EXCEEDED` | общий лимит 20 запросов / 15 минут на адрес, общий с `/api/voice/*` | подождать; отдельного лимита для Shortcut нет |
| Нет ответа / таймаут | ПК выключен или Tailscale на iPhone выключен | включить Tailscale; если ПК выключен — записать через Telegram (варианты A–C) |
| Сервер не стартует после правки `.env.local` | токен короче 32 символов, одна переменная без другой или владелец не из списка | прочитать ошибку в логе сервиса и поправить |

#### Что даёт и чего нет

1. **Токен один на сервер и привязан к одному владельцу.** Держатель токена пишет только владельцу и не может выбрать
   другого. Персональных токенов на устройство, срока жизни и журнала нет — при одном пользователе они не нужны.
2. **Токен лежит на телефоне в открытом виде** внутри Shortcut — его видно любому, кто откроет команду. Поэтому
   отзыв сделан правкой одной строки и перезапуском, а API открыт только в tailnet.
3. **Rate limit общий на адрес** (20 / 15 минут, делится с `/api/voice/*`) — отдельной политики для не-Telegram
   источника нет.
4. **Повтор без дублей — только с `clientId`.** Без него каждый запуск — новая запись.
5. **ПК включён «как получится».** Когда он выключен, запрос не доходит; очередь записей на телефоне даст
   iOS-приложение (FT-161).

**Никогда не класть в Shortcut:** `TG_BOT_API_KEY`, `OPENAI_API_KEY`, заголовок `X-Dev-User-Id`, cookie/`initData`
из Mini App. Первые два — ключи ко всему боту и к платному API, третий в production не действует вовсе, четвёртый
протухает через час и всё равно не предназначен для переноса на устройство. `X-Shortcut-Capture-Token` —
единственный секрет, который сюда попадает, и он отзывается правкой одной строки в `.env.local`.

## Альтернатива без Shortcut вообще

Иногда быстрее не строить цепочку, а писать боту напрямую:

- **Голосовое боту.** Открыть чат с ботом → удерживать микрофон → сказать «такси 18 тысяч» → отпустить.
  Бот транскрибирует и отвечает тем же подтверждением. Это единственный работающий голосовой ввод — в Mini App
  диктовки нет, микрофон в поле ввода на главной честно отправляет за этим в чат бота (`FT-114`, до `FT-117`).
- **Диктовка в поле ввода Telegram.** Открыть чат бота → микрофон на клавиатуре → продиктовать текст → отправить.
- **Виджет Telegram** с закреплённым чатом бота на домашнем экране — открывает чат в одно нажатие.
- **Mini App**, если телефон уже в руках и нужен не только ввод, но и просмотр.

Для многих сценариев «виджет Telegram + диктовка» оказывается не медленнее Shortcut. Стоит сравнить оба на практике,
прежде чем закреплять Кнопку действия.

## Чек-лист проверки на реальном iPhone

Прогнать после настройки. Бот при этом должен быть запущен локально (`npm run serve` или
`npm run dev:miniapp -- --chat-id=<id>`).

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Запустить команду из приложения «Быстрые команды» | Появляется вопрос «Что потратил?» |
| 2 | Напечатать `такси 18к`, подтвердить | Открывается Telegram, чат с ботом |
| 3 | Долгое нажатие на поле ввода → «Вставить» | В поле подставился ровно `такси 18к` |
| 4 | Отправить | Бот отвечает `Записал` · `Такси · 18 000 сум · Транспорт` |
| 5 | Открыть Mini App → «Недавние» | Та же операция в списке, сумма 18 000, категория «Транспорт» |
| 6 | Повторить через диктовку (микрофон на клавиатуре) | Текст распознан, результат как в шагах 4–5 |
| 7 | Запустить ту же команду Кнопкой действия / касанием задней панели | Поведение идентично шагу 1 |
| 8 | Отправить боту голосовое «кофе 35 тысяч» | Ответ с префиксом 🎤 и тем же форматом подтверждения |
| 9 | Отправить бессмысленный текст (`привет`) | Бот отвечает «Не нашёл операцию», в базе ничего не создано |
| 10 | Включить авиарежим, запустить команду, отправить | Telegram ставит сообщение в очередь; после возврата сети оно уходит, бот отвечает |
| 11 | Остановить бота локально, отправить трату, запустить бота | Сообщение обрабатывается после старта (Telegram хранит апдейты до 24 часов); **дата операции — день отправки сообщения**, а не день обработки (FT-182) |

Шаги 5, 9 и 11 — самые важные: они проверяют, что запись реально дошла до базы, что мусор не создаёт операций и
что задержка не искажает дату.

### Вариант D — прямой вызов API (FT-160)

Прогнать на живом экземпляре: в `.env.local` заданы `SHORTCUT_CAPTURE_TOKEN` и `SHORTCUT_CAPTURE_OWNER`, сервис
перезапущен, Tailscale на iPhone включён.

| # | Шаг | Ожидаемый результат |
|---|---|---|
| D1 | Запустить команду варианта D, ввести `такси 18к` | Уведомление `Записал`; Telegram не открывается |
| D2 | Открыть Mini App → главная | Та же операция в «Последних», 18 000, «Транспорт» |
| D3 | Запустить Кнопкой действия, продиктовать `кофе 25 тысяч` | Уведомление `Записал`, запись в Mini App |
| D4 | Ввести `привет` | Уведомление `Не нашёл операцию`, в Mini App ничего нового |
| D5 | Ввести `кофе 25к и такси 18к` | `Записал 2`, в Mini App две записи |
| D6 | Выключить Tailscale на iPhone, запустить команду | Ошибка соединения, ничего не записано; включить Tailscale обратно |
| D7 | В команде поменять один символ токена, запустить | `401 INVALID_SHORTCUT_TOKEN` (или ошибка без `data.ack.title`), ничего не записано; вернуть токен |
| D8 | Добавить в команду заголовок `X-Shortcut-User-Id` с чужим id, запустить | `403 ACCESS_DENIED`, ничего не записано; убрать заголовок |
| D9 | Если в теле есть `clientId`: повторить тот же запрос внутри команды | Вторая запись не появилась, в ответе `repeated: true` |
| D10 | Отозвать токен (новый в `.env.local`, перезапуск), запустить старую команду | `401 INVALID_SHORTCUT_TOKEN`; после замены токена в команде — `Записал` |

Шаги D2, D4 и D7 — самые важные: запись дошла до базы, мусор не создаёт операций, чужой токен не пишет.

## Troubleshooting

| Симптом | Причина | Что делать |
|---|---|---|
| Telegram не открывается по ссылке | схема `tg://` не обработана | заменить URL на `https://t.me/<BOT_USERNAME>` |
| Открывается поиск/профиль вместо чата | опечатка в username или `@` в URL | username пишется без `@`, ровно как в профиле бота |
| Поле «Вставить» вставляет старое | «Скопировать» стоит после «Открыть URL» | порядок строгий: запросить ввод → скопировать → открыть URL |
| Telegram не даёт писать в чат | боту ни разу не отправляли `/start` | открыть чат с ботом и нажать «Начать» / `/start` |
| Бот молчит | локальный процесс не запущен | запустить `npm run serve` или `npm run dev:miniapp -- --chat-id=<id>`; отправленное ранее обработается после старта |
| «Не нашёл операцию» | в тексте нет суммы | писать сумму явно: `такси 18к`, `кофе 35000` |
| Сумма распознана неверно | сокращение непонятно парсеру | использовать `18к` / `18000` / `18 тысяч` и проверить результат |
| Категория не та | ошибка классификации | поправить кнопками под сообщением бота или в Mini App — исправления идут в обучение |
| Бот отвечает про лимит | исчерпан лимит транзакций/голоса подписки | проверить лимиты в Mini App; политику лимитов менять только по решению Шукура |
| Дата операции не сегодняшняя | сообщение обработано позже отправки | указывать дату словами в тексте (`вчера такси 18к`) или править операцию в Mini App |
| Команда просит разрешение каждый раз | не выдано постоянное разрешение | разрешить открытие Telegram в диалоге iOS |

## Ограничения

1. **Не одно нажатие (варианты A–C).** Вставка и отправка остаются ручными; вариант C может убрать вставку, но не
   отправку. Полностью автоматический флоу даёт только [вариант D](#вариант-d--прямой-вызов-api-одно-нажатие):
   токен владельца, адрес в tailnet, ПК должен быть включён (`FT-075`, `FT-155`).
2. **Зависит от локального процесса.** Пока бот работает на WSL через polling, запись обрабатывается только когда
   процесс запущен. Сообщение не теряется (Telegram хранит апдейты до 24 часов), но подтверждение придёт с задержкой.
3. **Дата — время отправки сообщения (варианты A–C).** Бот датирует запись временем, когда Telegram принял
   сообщение (`message.date`, FT-182), а не временем обработки. Трата, отправленная вечером при выключенном ПК, ляжет
   тем же вечером, хотя бот прочитает её утром. Прямой вызов (вариант D) передаёт время ввода в `capturedAt` (FT-175,
   [контракт](QUICK_CAPTURE_API.md#time-of-input-capturedat)). Пределы у обоих одни.
4. **Нет идемпотентности в Telegram.** Повторная отправка того же текста боту создаст вторую операцию — дублей
   парсер не отсекает. В варианте D повтор с тем же `clientId` новой записи не создаёт.
5. **Буфер обмена перезаписывается** (вариант A). Если в буфере лежало что-то нужное — оно потеряется.
6. **Нет офлайн-подтверждения.** Telegram отправит сообщение позже, но до этого нет никакой гарантии, что трата
   записана; проверять по ответу бота, а не по факту отправки.
7. **Shortcut ничего не знает о результате.** Он не читает ответ бота, поэтому ошибку распознавания видно только
   в чате.

## Что нельзя проверить из WSL

Всё, что ниже, проверяется только на устройстве — в этом документе это предположения, а не подтверждённые факты:

- поведение `tg://resolve?...` и `?text=` префилла в текущей версии Telegram для iOS;
- точные названия пунктов меню в приложении «Быстрые команды» и в «Настройках» текущей версии iOS;
- доступность экрана «Кнопка действия» на конкретной модели iPhone;
- качество диктовки и распознавания Siri для русских формулировок сумм;
- реальная скорость флоу в сравнении с «виджет Telegram + диктовка».

- поведение варианта D на самом телефоне: доступность адреса tailnet при включённом Tailscale, точная форма
  действия «Получить содержимое URL» и форматирования даты для `clientId` в текущей версии iOS (FT-160).

Проверено по коду и тестами репозитория (а не предположено): маршрутизация текста бота в Quick Capture, пропуск
сообщений, начинающихся с `/`, общий per-IP rate limit, время ввода `capturedAt` (FT-175), а также поведение варианта D —
запись на владельца по токену в production, `403` на чужой `X-Shortcut-User-Id`, `401` на неверный или пустой
токен, повтор `clientId` без дублей, `X-Dev-User-Id` без действия в production, ошибка запуска при неполной
настройке (`tests/shortcutCaptureOwner.test.ts`, `tests/quickCaptureRoutes.test.ts`, `tests/localDevAuth.test.ts`).
