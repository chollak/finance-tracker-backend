# Как устроена доска задач

`TASKS.md` в корне — единственный источник правды по текущей работе. GitHub Issues, Project и Wiki
могут содержать устаревшее январское планирование: обращаться к ним только когда задача явно просит
их сверить (например FT-049).

## Где что лежит

| Файл | Что внутри | Кто пишет |
|---|---|---|
| [`../../TASKS.md`](../../TASKS.md) | Задача в работе, очередь, список backlog | Hermes |
| [`decisions.md`](decisions.md) | Лог решений, менявших направление; новые сверху | Hermes |
| [`backlog.md`](backlog.md) | Отложенные задачи с полными описаниями | Hermes |
| [`archive/`](archive/) | Закрытые задачи с отчётами «Реализовано / Проверка» | Hermes при закрытии |

Правило разделения простое: **в `TASKS.md` живёт только то, над чем идёт или пойдёт работа.**
Задача закрыта — её тело целиком переезжает в соответствующий файл `archive/`, а не остаётся с пометкой
`done`. Задача снята с очереди — переезжает в `backlog.md`, в доске от неё остаётся строка таблицы.

## Статусы

Положение задачи в `TASKS.md` — основной признак состояния: раздел «В работе», «Очередь» или строка
в таблице backlog. Поле `Status:` уточняет детали внутри этого положения:

| Статус | Значение |
|---|---|
| `in_progress` | Claude Code работает прямо сейчас |
| `review` | реализовано, Hermes проверяет |
| `needs_fix` | Hermes нашёл проблему, задача вернулась в работу |
| `blocked` | нужен ответ или решение Шукура |
| `backlog` | описана, но не запланирована |
| `done` | Hermes независимо подтвердил результат — задача уезжает в `archive/` |
| `cancelled` | потеряла смысл; причина и уцелевшие части записаны в теле |

## Роли

- **Hermes** ведёт доску, формулирует задачи, делает финальный QA gate, коммитит и пушит.
- **Claude Code** реализует ровно одну описанную задачу за раз узкими TDD-срезами.
- Claude Code может запускать тесты, но **не переводит задачу в `done` сам**.

## Правила

- Перед началом работы прочитать «Текущий фокус» в `TASKS.md`.
- Одна задача за раз.
- Перед `done` Hermes проверяет реальный вывод: diff, точечные тесты, `npm run verify`, при
  необходимости скриншот-QA или API smoke.
- Без явного разрешения не делать force push, reset, удаление веток и файлов, деплой и применение
  внешних миграций БД.
- Задачи с продуктовым решением держать в backlog до явного решения Шукура.

## Формат задачи

```markdown
### FT-XXX: Короткое название на английском

Status: in_progress
Priority: high | medium | low
Owner: Claude Code, QA by Hermes
Type: bug | feature | repo-hygiene | quick-action-ui | design-system | ...

Context:
Что не так и почему это важно. Ссылки на файлы и строки.

Definition of Done:
- [ ] Проверяемые пункты, а не намерения
```

При закрытии Hermes дописывает в тело разделы «Реализовано» (что и почему сделано именно так) и
«Проверка» (что реально запускалось и с каким результатом), после чего переносит задачу в `archive/`.
