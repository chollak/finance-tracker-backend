### 2026-10-20 — «?» у категории и «Назад» на проверке записей

- **«?» у категории** на проверке записей — только когда категорию угадал ИИ. Совпадение по словарю синонимов
  или по выученному паттерну пользователя «?» не даёт. Сделано после FT-114 иначе (любая неназванная
  категория), поэтому правка — задача FT-138.
- **«Назад» на проверке записей** отменяет записи фразы и возвращает текст в поле — как сделано в FT-114.

  другой экран; их код живёт в `main`, пока его не заменят FT-110 и FT-125. FT-083…FT-085 отменены, их цели

Следствия для правил репозитория: стоп «broad Home/product IA decisions» больше не касается экранов,

### 2026-09-04 — dev/test Shortcut capture API (FT-075); продовая auth остаётся решением Шукура

Ревизия 2026-09-04 после FT-075 (dev/test): прямой вызов `POST /api/quick-capture` из iPhone Shortcut реализован **только для локального dev/test контура**. Заголовок `X-Shortcut-User-Id` задаёт владельца записи и принудительно ставит `source=ios_shortcut`; опциональный общий токен `SHORTCUT_CAPTURE_TOKEN` проверяется через `X-Shortcut-Capture-Token`; при `NODE_ENV=production` весь обход отвергается с 403 `SHORTCUT_CAPTURE_DISABLED`. Это **не продовая auth-модель** и не отменяет вопросы из блокирующего списка — просто они больше не блокируют локальное использование. Безопасный план quick-capture закрыт полностью (FT-073, FT-074, FT-076, FT-075 dev/test). Оставшийся продовый токен (выдача, срок жизни, отзыв, rate limit для не-Telegram источника) — будущее решение Шукура, а не текущий блокер. Активная очередь остаётся **FT-059 → FT-060 → FT-061**.

## Обоснование вех 0 и 1

Веха 0 появилась после сквозного тестирования: редактирование транзакции и возврат из архива не работают вовсе, а суммы вида «12 млн» сохраняются как 12. Это ломает работу с данными раньше, чем начинаются вопросы к их интерпретации.
