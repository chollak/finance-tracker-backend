### FT-087: Fix category update, bot delete and double usage count

Status: done
Priority: high
Owner: Claude Code, QA by Hermes
Type: bug
Size: S

Context:
Смена категории теряется на SQLite (`SqliteTransactionRepository.update()` без ветки `category`). «Удалить»
в боте не работает: `callbackHandlers.ts:124` передаёт строку вместо `{ id }`, а «последняя запись»
сохраняется по UUID (`messageHandlers.ts`), читается по telegramId (`callbackHandlers.ts:113`). Счётчик
free-лимита растёт дважды (`createTransaction.ts`, обработчики бота, middleware `POST /transactions`).

Definition of Done:
- [x] PUT с новой категорией меняет её на SQLite; тест репозитория
- [x] «Удалить» в боте удаляет запись и снимает кнопки; тест обработчика
- [x] Одна запись увеличивает счётчик ровно на 1 при любом пути ввода; тест
- [x] `npm run verify` проходит

Реализовано 2026-10-16 (`eadc914`, PR #86):
- `SqliteTransactionRepository.update()` пишет `category` — смена категории больше не теряется на SQLite.
- «Удалить» в боте: последняя запись хранится по Telegram id (его одного знает callback), use case получает `{ id }`,
  неудачное удаление больше не отвечает «Удалено» и даёт повторить.
- Запись считается в лимите только в `CreateTransactionUseCase`; обработчики текста, голоса и быстрой записи в боте и
  middleware `POST /api/transactions` второй раз её не считают. Голосовые вводы по-прежнему считает голосовой обработчик.
- Кнопку «Удалить» потом заменила «Отменить» с мягким удалением (FT-122, FT-105).

Проверка:
- Новые тесты сначала падали, потом прошли: `sqliteTransactionRepositoryUpdate`, `telegramDeleteCallback` (запись
  удалена, кнопки сняты), `usageCounting`. `npm run verify` в PR #86: Jest 37 наборов / 443 теста, Vitest 20 файлов.
- Ревью отдельным агентом в PR не записано. «Удалить» в боте вживую не проверяли (пункт PR #86 остался открытым);
  отмену записи в боте после FT-122 проверили вживую 2026-10-26.
